# Промпт для объединения скиллов

Воспроизводимый промпт для будущих объединений набора скиллов с приоритетом более новой версии.

---

**Роль:** ты инженер репозитория `cc-1c-skills` (набор скиллов для 1С). Задача — объединить скиллы из нескольких источников, **приоритет — более новая версия**, результат должен проходить все guard-тесты.

**Контекст (проверять, не считать догмой):**
- `E:\project\cc-1c-skills` — рабочая копия (форк `legavaz`). Канонический апстрим: `https://github.com/Nikolay-Shirokov/cc-1c-skills` (`upstream/main`). Другие порты апстрима — ветки `port-*` (напр. `port-opencode`, `port-opencode-py`).
- Каталог `C:\Users\lega\.config\opencode\skills` — **сгенерированный** opencode-порт (`scripts/switch.py`), может быть **старее** апстрима. Не считать его «самым новым» априори.
- Конвенция путей: в репозитории (`.claude/skills`) — канон `${CLAUDE_SKILL_DIR}/` (кросс-скилл: `${CLAUDE_SKILL_DIR}/../<other>/`). В `port-opencode` — `.opencode/skills/<skill>/`. Иные агенты генерируются `switch.py`.
- Переводы строк в репо — LF (`.gitattributes` `eol=lf`); внешние сборки часто CRLF — нормализовать в LF.

**Шаги:**
1. **Определи новизну по версии**, а не по расположению: возьми маркер `# <skill> vX.Y` из шапки `.py`/`.ps1` каждого источника. Составь таблицу версий. «Новее» — только по номеру.
2. **Сравни с апстримом:** `git ls-remote --heads https://github.com/Nikolay-Shirokov/cc-1c-skills.git`, затем `git fetch --no-tags <url> main:refs/remotes/upstream/main`. Проверь: `git merge-base --is-ancestor HEAD upstream/main` и `git rev-list --count HEAD..upstream/main`.
3. **Если форк отстаёт от `upstream/main` без своих коммитов — сделай `git merge --ff-only upstream/main`** (это и есть «самое новое»; обычно вместе со скиллами идут согласованные `docs/` и `tests/`, без которых guard-ы не позеленеют).
4. **Собери union состава:** сравни имена каталогов скиллов во всех источниках. Добавляй только те, которых нет ни в апстриме, ни в его `port-*` ветках (проверяй `git ls-tree`).
5. **Портирование добавленных скиллов в канон:** из источника бери файлы, переведи CRLF→LF, сохрани BOM если был, и замени пути: `.opencode/skills/<self>/` → `${CLAUDE_SKILL_DIR}/`, `.opencode/skills/<other>/` → `${CLAUDE_SKILL_DIR}/../<other>/`. Скрипты путей не содержат — их не трогать. Проверь `grep`: остатков `opencode` — 0; `claude` вне `${CLAUDE_SKILL_DIR}` — 0.
6. **Не удаляй существующее молча:** если в одной версии есть файлы, которых нет в другой (напр. пере-раскладка `reference/`), оставляй новую структуру, а устаревшие дубли удаляй явным списком.
7. **Прогони `node tests/skills/check-all.mjs` (обязательно зелёный; при падении не коммитить).** Типовые починки:
   - `check-inline-drift`: новые потребители общих хелперов не зарегистрированы — добавь в `tests/skills/check-inline-drift.mjs` (для одного порта — `consumersPy`/`consumersPs1`). Если тело расходится с эталоном — приведи хелпер к эталонной реализации.
   - `check-type-maps` / `check-form-purposes` / `check-typeset-coverage`: новый тип/назначение не описан — правь `docs/*.md` (спека — эталон).
   - `check-ps-portability`: db-*/epf-* .ps1, запускающие платформу, обязаны иметь верхнеуровневый `trap { … exit 1 }`; `$env:TEMP/TMP` запрещены — брать `[IO.Path]::GetTempPath()`.
   - `check-error-streams`, `check-ps-define-before-call`, `check-nonascii-fs`, `check-uuid-invariant` и т.д. — смотри текст ошибки, правь соответствующий порт/реестр.
8. **Обнови инвентарь:** добавь новые скиллы в дерево `README.md` (и, если есть, в индексы/гайды).
9. **Один коммит** в стиле репо (`feat(skills): …`, `fix(<skill>): …`, `docs(...): …`) с перечнем: что синхронизировано, какие скиллы добавлены, какие реестры/docs поправлены. **Пуш только по явной просьбе.**
10. **Проверка чистоты:** `git status` без лишнего; 0 остаточных `.opencode`; все guard-ы OK.

**Запрещено:** автопуш без просьбы; слепой перенос из глобальной сборки без сверки версий; хардкод `.opencode/skills` в `.claude/skills` (сломает `switch.py` и портируемость); коммит при красных guard-ах.

**Итог отчитай так:** таблица источников и версий → что fast-forward'ом, что добавлено → какие guard-ы падали и как починены → hash коммита → итоговое число скиллов.
