# /db-eventlog — Журнал регистрации через ibcmd

Выгружает журнал регистрации в `xml` или `json`, а также XSD-схему модели событий.
Работает **только движком ibcmd** (режим `eventlog`) — движок навыка не переключается.

## Ключевое отличие от остальных навыков `db-*`

`ibcmd eventlog export` читает **каталог журнала регистрации**, а не информационную базу:
позиционный параметр команды — путь к каталогу журнала (обычно `<каталог данных сервера>\log-data`).
Поэтому `-LogPath` (или `-DataDir`) обязателен, а реквизиты базы (`-InfoBasePath`, `-UserName`,
`-Password`) навыку не нужны.

> ⚠️ **Ограничение по базам проекта.** Журнал кластерных серверных баз (`localhost\GitConv`,
> `localhost\task`) лежит в СУБД, а не в каталоге на диске, и `ibcmd eventlog export` его не видит.
> Для них работает MCP-1С (`get_event_log`) в живом сеансе. Этот навык — для файловых баз и
> автономных серверов, в том числе в CI.

## Usage

```
/db-eventlog <logPath> [-From <дата>] [-To <дата>] [-Out <файл>]
/db-eventlog <logPath> -Format json -SkipRoot -Out "C:\WS\events.json"
/db-eventlog model -Out "C:\WS\events.xsd" <logPath>
```

## Параметры подключения

1. Если пользователь указал путь к журналу или каталогу данных — используй напрямую
2. Если указал только имя базы — ищи по id / alias / name в `.v8-project.json`; платформа — `v8path` записи
3. Если не указал — спроси: путь к журналу узнать нельзя, каталог данных навык не угадывает
4. Путь к `ibcmd` — из `-V8Path`; если не передан, навык ищет `ibcmd.exe` рядом с `1cv8`
   (в `C:\Program Files\1cv8\<версия>\bin`, затем в `C:\Program Files\1cv8\ibcmd.exe`);
   на *nix — `/opt/1cv8/<версия>/bin/ibcmd`. Если файла нет — сообщи и предложи установку

## Команда

```powershell
powershell.exe -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/db-eventlog.ps1" <параметры>
```

### Параметры скрипта

| Параметр | Обязательный | Описание |
|----------|:------------:|----------|
| `-Command <команда>` | нет | `export` (по умолчанию) — выгрузка событий; `model` — XSD-схема модели событий |
| `-V8Path <путь>` | нет | Путь к `ibcmd.exe`, каталог `bin` платформы или каталог `1cv8` — ищет `ibcmd` рядом |
| `-LogPath <путь>` | * | Каталог журнала регистрации (позиционный параметр `ibcmd eventlog export`) |
| `-DataDir <путь>` | * | Каталог данных сервера: журнал берётся из `<DataDir>\log-data` |
| `-Format <формат>` | нет | `xml` (по умолчанию у ibcmd) / `json` |
| `-From <дата>` | нет | Начало периода: `ГГГГ-ММ-ДД` или `ГГГГ-ММ-ДДЧч:мм:сс[.мммммм]`; «просто дата» = начало суток |
| `-To <дата>` | нет | Конец периода в том же формате; «просто дата» = конец суток |
| `-Out <файл>` | нет | Файл выгрузки; без него вывод идёт в stdout |
| `-SkipRoot` | нет | Пропустить корневой элемент: каждое событие — самостоятельная сущность формата |
| `-Follow <мс>` | нет | Ожидание новых событий с частотой `<мс>` (для наблюдения в реальном времени) |
| `-AdditionalIbcmdArguments <список>` | нет | Доп. аргументы `ibcmd` через запятую, в форме `--ключ=значение` |

> `*` — нужен либо `-LogPath`, либо `-DataDir`

### Коды возврата

| Код | Значение |
|-----|----------|
| `0` | выгрузка выполнена; файл создан и непуст (либо вывод напечатан в stdout) |
| `1` | ошибка запуска/разбора параметров либо файл не создан при коде 0 платформы |
| `2` | платформа отработала без событий: файл пуст или вывода нет |
| прочие | код платформы; при аварийном завершении добавляется пояснение `describe_exit` |

## Примеры

```powershell
# Выгрузка за день в xml
powershell.exe -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/db-eventlog.ps1" -V8Path "C:\Program Files\1cv8\8.3.27.2214\bin\ibcmd.exe" -LogPath "E:\srv\standalone-server\log-data" -From 2026-10-02 -To 2026-10-02 -Out "E:\WS\events.xml"

# Каждое событие отдельным объектом json (удобно разбирать без XML-запросов)
powershell.exe -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/db-eventlog.ps1" -LogPath "E:\srv\standalone-server\log-data" -Format json -SkipRoot -Out "E:\WS\events.json"

# Каталог данных вместо пути к журналу
powershell.exe -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/db-eventlog.ps1" -DataDir "E:\srv\standalone-server" -Out "E:\WS\events.xml"

# XSD-схема модели событий (нужна для разбора выгрузки внешними средствами)
powershell.exe -NoProfile -File "${CLAUDE_SKILL_DIR}/scripts/db-eventlog.ps1" -Command model -LogPath "E:\srv\standalone-server\log-data" -Out "E:\WS\events.xsd"
```

## Проверенные особенности платформы (8.3.27.2214)

| Особенность | Следствие |
|---|---|
| Режим `eventlog` **не принимает** `--data` (и вообще параметры подключения к базе): только `--pid` / `--remote` либо позиционный каталог журнала | навык не передаёт `--data`; попытка добавить его в `-AdditionalIbcmdArguments` даёт «Ошибка разбора параметра» |
| Выгрузка за период без событий всё равно создаёт валидный файл (скелет XML/JSON) | код `0`; признак «событий не было» — сверять с содержимым, а не с размером |
| `-Follow` без платформенных оповещений работает как периодический опрос | для наблюдения в реальном времени запускай навык повторно с интервалом |
